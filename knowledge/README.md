# Workstation knowledge base

Use these references on demand. They describe decision criteria, not authorization to mutate a machine. Current engine capability must be discovered before a command is invoked.

- [Measurements and accounting](measurements.md): validity, allocation, hard links, placeholders and coverage.
- [Action and preservation rules](actions.md): caches, originals, worktrees, runtimes, compression and cloud transfers.
- [Workflow playbooks](playbooks.md): diagnosis, recovery batches, project focus and sustained performance.
- [Platform support and distribution](platform-support.md): official skill/plugin mechanisms, validation and submission status.

Each substantive update should include its source, last verification date, platform/version scope, known limitations and a regression or example where useful. Vendor documentation outranks a stale command copied from another workstation. Observed, inferred, tested, supported and approved are separate evidence states.

Keep examples synthetic and local by default. This is a public reference library, not a copy of a user's private machine inventory or operational memory. Large case studies belong in linked references only when their publication is authorized and sensitive details are removed.
